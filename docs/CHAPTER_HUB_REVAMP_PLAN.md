## 1. Chapter identity — "Chapter 4"

**Rule:** the number a student sees is the chapter's curriculum `order`, never parsed out of the
code (codes are subject/volume scoped: `SCI-10-4`, `MAT-8P2-3`). The code stays as a small
secondary label because teachers use it.

Surfaces:

| Surface | Change |
|---|---|
| Web hub header | `CHAPTER {order}` pill **above** the title; code moves to a low-contrast chip next to the subject line. Breadcrumb becomes `Class 10 › Science › Chapter 4`. |
| Mobile hub header | Eyebrow becomes `Class 10 • Science • Chapter 4`; the code chip stays below the title but loses the visual weight. |
| Web chapter list | Number badge (like mobile) + `Chapter {order}` in the meta line; `chapter.code` becomes muted. |
| Mobile chapter list | Badge keeps `{order}`, meta line gains `Chapter {order} • {conceptCount} concepts`. |

No API change (both payloads already carry `order`).

## 2. Chapter hub order — one scroll, seven blocks

**Decided order** (identical web + mobile):

```
1. Header            Chapter N · name · subject/class · mastery %
2. Continue          one card: weakest/first unmastered concept + progress bar + CTA
3. Contents          every concept, curriculum order, serial + duration + range
4. Learn             video lessons (vertical markers) · Read the textbook · 3D model(s)
5. Practise          one whole-chapter practice set (+ honest empty state)
6. Ask               Ask Sanro AI about this chapter
7. Chapter notes     collapsed by default ("Show chapter notes"), expand = full revision sheet
```

Why:

- **Continue → Contents → Learn** is the learning loop (what to do → what exists → do it).
  A student scanning the hub first needs "where am I", then the chapter's map.
- **Practise before Ask** — practice produces the diagnosis; Ask is the fallback when stuck.
- **Notes last** — the notes are a long reference sheet (chapter description + every concept's
  notes, generated by `buildChapterSummary`). At the top they push every actionable item below
  the fold. Collapsed-by-default keeps them one tap away without dominating the page.
- **The `Actions` card is removed**; its three rows become the Learn/Practise/Ask blocks
  (textbook moves into Learn, practice owns Practise, AI owns Ask). No duplicate affordances.

This supersedes `FEATURE_CHAPTER_HUB.md` §3 (which put notes at the top of Learn).

Empty-state rule unchanged: a block with no data renders its own empty state and nothing else.

## 3. Concept rows — serial, duration, start–end

### 3.1 API contract

`GET /learning/chapters/:chapterId` → each item in `concepts[]` gains:

```ts
section: {
  contentId: string;      // the video that contains this concept
  startSeconds: number;   // where the concept begins
  endSeconds: number;     // next marker, or the video duration
  durationSeconds: number;// endSeconds - startSeconds
  derived: boolean;       // true when the split came from deriveConceptSegments
} | null
```

Mapping rules (`apps/api/src/learning/learning.service.ts`, next to the existing video mapping):

1. For each video, normalize segments (`normalizeChapterSegments`, already there).
2. Match a segment title to a concept name: lowercase, strip punctuation/whitespace, compare.
3. If the video's segments are **derived** (titles are the concept names in order), fall back to
   index matching — derived segments are built from `concepts.map(c => c.name)`, so index is exact.
4. `endSeconds` = next segment's `startSeconds`, else the stored `durationSeconds`
   (clamped, never negative).
5. No match → `section: null`. **Never invent a range.**

Also expose the same value on `topics[].concepts[]` (the payload already nests concepts there) so
nothing has to be recomputed later.

### 3.2 Presentation

Wide (web / tablet):

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ (04)  Types of Chemical Reactions            12:30 – 18:05        30:12      │
│       video lesson · Not started                        [ 42% developing ] › │
└──────────────────────────────────────────────────────────────────────────────┘
```

Narrow (phone), two lines:

```
┌──────────────────────────────────────────────┐
│ (04)  Types of Chemical Reactions        ›   │
│       30:12 · 12:30 – 18:05      [42%]       │
└──────────────────────────────────────────────┘
```

- `(04)` = curriculum order, zero-padded badge.
- Left of the meta line = **concept duration**; right = **start – end** in the video.
- A concept with no video: meta line is `No video · {status}` and no times.
- The whole row is the link; no separate play button (the tap already starts playback — §4).
- Web keeps the mastery badge on the right; on mobile it wraps to the second line.

Helpers: `formatClock(seconds)` (already exists as `formatTimestamp` in
`apps/mobile/lib/chapter-hub.ts`; the web equivalent lives in `lib/video-segments.ts`) — reuse,
do not fork.

## 4. Opening a concept starts that concept's part of the video

### 4.1 Navigation contract

`/app/learn/concepts/:id?t=<startSeconds>&video=<contentId>` (web) and
`/concept/:id?t=…&video=…` (mobile). The hub builds it from `concept.section`.
Deep links without `t` behave exactly as today.

### 4.2 Player

`YouTubePlayer` (mobile) and `VideoWithSegments` (web) gain:

```ts
startSeconds?: number;   // initial position
autoPlay?: boolean;      // true only when arriving from a concept row
```

- Embed URL gains `&start={t}&autoplay=1` when `startSeconds > 0`; the wrapper's
  `seekScript` is still posted after load (belt and braces — the iframe can drop the first seek).
- Mobile: the player skips the thumbnail state and mounts the WebView immediately
  (`mediaPlaybackRequiresUserAction={false}` already allows autoplay).
- Web: the iframe starts at `t`; if the browser blocks autoplay the poster remains and pressing
  play starts at `t` (never 0).
- A small chip under the player: `Starting at 12:30 · Section 4` + `Play from the start` link
  that reloads at 0.
- The concept's own segment is highlighted in the marker list (`activeStartSeconds = t`).

### 4.3 Concept page order (unchanged, but now purposeful)

Learn tab = **video(s)** → **3D model** → **study notes** (already true on both clients).
The first video is the one the hub linked (`video` param) — so the tap lands on the right lesson.

### 4.4 Fallbacks

| Situation | Behaviour |
|---|---|
| `t` missing | Play from 0 (today's behaviour) |
| `t` past the stored duration | Clamp to `duration - 5s` (the API already clips segments) |
| Concept has no section | Open the concept page normally, no chip |
| Video is a non-YouTube URL | Ignore `t` (no seek API) |

## 6. AI reply truncation

### 6.1 Root cause

`apps/api/src/ai/ai.service.ts:391` caps chat output at **1200 tokens**. A structured answer
(headings + lists + examples) exceeds that; Gemini stops with `finishReason: MAX_TOKENS` and the
text ends mid-sentence — which is also how an unmatched `**` reached the UI.

### 6.2 Fix

1. Chat cap → **4096 tokens** (JSON stays 2048; the 45 s abort stays).
2. `geminiGenerate` returns `finishReason`; `callGemini` passes it through; `remoteChat` returns
   `truncated: boolean` in the chat response (additive field, clients tolerate it).
3. When truncated, append a visible last line: `_(Answer shortened — tap Continue for the rest.)_`
   and let the client show a **Continue** chip that sends `continue`.
4. Keep `normalizeMarkdown`'s unmatched-delimiter cleanup as the safety net.
5. Test: mocked Gemini `finishReason: MAX_TOKENS` → `truncated: true`, marker appended, no crash;
   mocked `STOP` → unchanged.

### 6.3 Verify

Ask the reactivity-series question on device and on web; the answer must end with a complete
sentence (or the explicit truncated marker + Continue chip), never mid-word.

## 11. What actually shipped (2026-10-29) and what the plan missed

Every phase landed on both clients in one change. Three findings changed the plan:

### 11.1 `Chapter.order` was never written — every chapter held `0`

The plan assumed `order` existed and only needed printing. It did not: `seed.ts` created chapters
without `order`, so `SELECT DISTINCT "order" FROM "Chapter"` returned a single row, `0`, for all
209 chapters. "Chapter 0" would have shipped on every screen.

- The seed now writes `order` 1-based from the curriculum list (`chapterIndex + 1`), and repairs
  existing rows through the upsert `update`; topics and concepts moved to 1-based as well.
- The API never trusts a legacy `0`: `curriculumNumber(order, code, index)` falls back to the
  code's own numeric suffix (`SCI-10-4` → 4, `MAT-8P2-3` → 3), then to list position. An
  unseeded production database therefore still prints the right number.
- `concepts[].order` is the position in the **chapter**, not in the topic: per-topic numbering
  produced `1, 1, 2, 2` down a flat Contents list (caught by `chapter-hub-sections.e2e-spec.ts`).

### 11.2 A concept-owned compilation could swallow a concept

`buildConceptSections` originally did the "concept-owned video = the whole clip" fallback inside
the same loop as the marker matching. For `SCI-10-4` the chapter carries a 4 h 33 min compilation
that belongs to concept 1 *and* a 38 min lesson whose derived split covers all four concepts — the
first video won and concept 1 read **`00:00 – 4:33:18`**.

The matcher is now a module-level, unit-tested function with two passes: marker matches (creator
titles, then the derived index) for every video first, and the whole-clip fallback only for
concepts nothing named (`src/learning/concept-sections.spec.ts`, 6 cases).

### 11.3 `from-[#0b0614]/92` compiled to white

The chapter-hub header and the dashboard hero used
`bg-gradient-to-r from-[#0b0614]/92 …`. In this Tailwind build the arbitrary hex + opacity
gradient stops resolved to `rgb(250,250,250)` → `rgb(255,255,255)`, so both banners rendered as a
**white card with white text** (the title was invisible; only the `bg-white` chip and the icon
survived). `bg-surface-950` was also undefined (`surface` stops at `900`), so nothing darkened the
photo either.

Both banners now set the base colour and the overlay with an inline `style` (rgba stops), which
cannot be mis-compiled. Any new banner should do the same rather than rely on arbitrary-alpha
gradient utilities.

### 11.4 Extras that were not in the plan

- **Section lists collapse on the hub.** The first video has 14 creator chapters; expanded, the
  Learn block pushed Practise two screens down and left a dead column beside the shorter video.
  `VideoSegments` (web) and `ChapterMarkerStrip` (mobile) take `collapsible` and start closed on
  the hub only — the concept page still shows every marker open.
- **The dashboard's "Continue Learning" cards are the Library subject card.** They used a compact
  text row, which made the same three subjects look like a different product. `SubjectProgressGrid`
  now renders the identical 16:9 photo banner, 3D icon and mastery footer, so one thumbnail size is
  reused everywhere (web + mobile `SubjectCard`).
- **Photo legibility.** The first composite buried the photograph under a 0.66 dark base; the base
  is now `0.5` (plus a `0.10` tint) so the science lab / mathematics chalkboard / English reading
  photo is recognisable while white text keeps contrast.
